## About Me

I'm a Computer Science graduate from **Columbia University** who builds systems that turn messy real-world inputs into useful workflows.

That has meant turning reels and saved places into shared maps, parsing clinical-trial documents into structured recommendation data, helping enterprise teams reason through payroll formula logic, modeling financial behavior from transactions, and building graphics/vision prototypes that understand scenes, motion, and constraints.

My work usually sits where **software engineering, AI/ML, product judgment, and implementation detail** meet. I like projects where the technical problem is only half the challenge — the other half is understanding the user workflow, the data shape, the constraints, and the decision the system is supposed to support.

**Current focus:** AI-powered products, backend/platform systems, RAG/data pipelines, LLM workflows and APIs, computer vision, graphics, ML systems, financial/data workflows, and tools that make complex systems easier to use.

## Featured Work

### 🗺️ [Roam](https://github.com/omondistanley/roam-mvp) — AI-Powered Social Planning

An AI-assisted planning system that turns reels, saved places, typed ideas, and shared maps into structured travel/social planning workflows.

- **Tech Stack:** Swift, React Native, React/Vite, FastAPI, PostgreSQL, Docker, Firebase Auth, Google Maps API, Vision LLM workflows
- **Core Work:** Extracted locations and activities from reels, resolved places through Google Maps, and stored structured outputs for planning workflows
- **Product Thinking:** Shared maps, saved places, friend invites, and calendar-aware planning reduce the friction between discovering a place and making a real plan
- **What it demonstrates:** Multimodal AI, LLM/API workflows, backend systems, product judgment, maps/location intelligence, and user-centered workflow design

### 💸 [Pocketii](https://github.com/omondistanley/pocketii) — Personal Finance Platform

A finance management platform for tracking transactions, surfacing spending patterns, detecting anomalies, forecasting spend, and generating AI-assisted insights.

- **Tech Stack:** FastAPI, PostgreSQL, Docker, Redis, JWT, Python, OCR, LLM-backed recommendations, Brave Search, Plaid/Teller/TrueLayer-style integrations
- **Core Work:** Built backend services for transaction ingestion, budgeting, portfolio monitoring, anomaly detection, forecasting, investment recommendations, and AI-powered financial summaries
- **Systems Thinking:** Rate limiting, encryption, idempotency keys, provider-failover thinking, JWT/session security, CI/testing workflows, and structured financial data pipelines
- **What it demonstrates:** Backend/platform engineering, financial systems, LLM-backed recommendation workflows, data reasoning, and practical product value

### 📺 [Creatures in the TV / CITV](https://github.com/omondistanley/citv) — Visual Computing Research Prototype

A research-oriented graphics/vision project exploring how animated agents can be inserted into TV/art scenes with scene-aware behavior.

- **Tech Stack:** Python, OpenCV, GroundingDINO, SAM2, Depth Anything V2, Florence-2, RAM++, Pix2SG, CUDA, scene JSON, local vision pipelines
- **Core Work:** Built scene-understanding pipelines using masks, depth, semantic labels, 2D/3D coordinates, relations, optional regions, path exports, captions, and motion-path constraints
- **Research Thinking:** Bridges computer vision, graphics, interaction design, creative software, local model pipelines, and real-time system constraints
- **What it demonstrates:** Research engineering, visual systems thinking, technical creativity, GPU-aware implementation, and comfort with ambiguous prototypes

### 🧠 [MistralMoE](https://github.com/omondistanley/MistralMoE) — Sparse MoE + Knowledge Distillation

A model-systems project exploring sparse upcycling, distillation, and efficient evaluation for Mixture-of-Experts language models.

- **Tech Stack:** PyTorch, Transformers, PEFT/LoRA, W&B, TensorBoard, vLLM-style inference/evaluation workflows, MMLU benchmarking
- **Core Work:** Upcycled a dense Mistral-style model into sparse MoE variants and evaluated routing, expert count, layer placement, FLOPs, throughput, and accuracy tradeoffs
- **ML Systems Thinking:** Focused on sparse activation, expert routing, load balancing, KD loss design, benchmark movement, GPU memory, and practical model-efficiency tradeoffs
- **What it demonstrates:** Foundation-model literacy, model efficiency, evaluation discipline, training-design reasoning, and LLM systems depth

### 🧊 [Neural Volume Rendering + Transfer Learning](https://github.com/omondistanley/Nerfs-and-transfer-learning) — Neural Rendering

Graphics/ML exploration of neural scene representation, rendering pipelines, and transfer-learning workflows.

- **Tech Stack:** Python, PyTorch, neural rendering, NeRF-style workflows, NumPy, Jupyter
- **Core Work:** Explored how learned representations can model scenes and support rendering from sparse visual observations
- **Graphics Thinking:** Connects machine learning with 3D visual understanding and computer graphics
- **What it demonstrates:** ML + graphics depth, spatial reasoning, and research-oriented implementation

### 🖼️ [Image Captioning with LSTM](https://github.com/omondistanley/Image-captioning-using-LSTM) — Vision + Language

An image-captioning system combining a CNN encoder with an LSTM decoder for generating natural-language descriptions from images.

- **Tech Stack:** Python, PyTorch, TorchVision, ResNet-18, LSTM, Flickr8k, NumPy, Pandas, Jupyter

## How I Design and Build

I like building from the workflow backward.

Before choosing a model, database schema, API, or interface, I try to understand the shape of the problem: what input is messy, what structure needs to be preserved, what the user is trying to decide, and where automation can reduce friction without hiding important context.

That mindset shows up across my work:

- In **Roam**, reels, saved places, and loose ideas become structured plans, maps, invites, and calendar-aware workflows.
- In **Pocketii**, transactions become budgets, anomalies, portfolio signals, forecasts, and financial recommendations.
- In **Sachi Health**, unstructured clinical-trial documents become normalized eligibility, intervention, and outcome data.
- In **Oracle Fusion HCM**, payroll formula logic becomes easier to create, explain, debug, and validate through AI-assisted workflows.
- In **CITV**, images become scene graphs with masks, depth, semantic labels, relations, coordinates, and motion constraints.
- In **Rhythmic**, product requirements become sprint-scoped features, messaging workflows, tests, and collaborative implementation decisions.

I care about systems that are technically strong but also legible: APIs that expose the right abstraction, interfaces that make the next action obvious, models that can be evaluated, and workflows that help people trust the output.
